# analysis_007 — 随机**因子集**对照（strategy_004 的 3 个新槽位随机化，20 种子）

## 生成（2026-10-13）

**main_idea**：承 strategy_004（迭代四 = 方案 B 六因子）的否结论 —— 它比基线差 11.9%
（共同区间 3.173x vs 3.600x）。但要小心**解释陷阱**：基线四因子本来就是被优化过的一组，
**随便动它大概率也会变差**。所以必须分开问：

> 这 −11.9% 是「**方案 B 挑得差**」，还是「**在这个骨架上换任何 3 个因子都会差**」？

**设计（唯一变量 = 3 个新槽位放哪个因子）**：
- 骨架固定 = `[turn_ratio, px_ma20, ?1, liq_amount, ?2, ?3]`（与 strategy_004 的 b6 逐项对齐）
- 三个随机槽从**库 512 因子**里抽（剔除方案 B 自己挑的 R076/R221/R222），
  每个用 **analysis_005 扫描出的该因子最优方向**（与当初选中 R076/R221/R222 的口径一致
  ⇒ 随机因子也拿"最好的一面"，是**更严**的零假设）
- 行业层 / 候选池 / 选股 / 缓冲 / 权重 / 成本 / 引擎 **全同 b6**（`shared/build_random_factor_targets.py`）
- 20 种子（1001~1020，可复现）；引擎 `run_weight_backtest` 进程内调用（行情只读一次）
- **★ 全部指标在共同区间（≥2017-05-12）**：新因子窗口短、随机因子也短 ⇒ 不控制会把不可比区间混进来

## ★ 结论：**推翻"方案 B 挑得差"的解释**

1. **方案 B 挑的 3 个因子是有效的** —— 净值/年化/Sharpe 全在随机因子集分布的 **95 分位**，
   回撤更是**最浅（100 分位）**。随机中位 2.00x vs 方案 B **3.17x（+58.8%）**，且 **超过了 P95(2.50x)**。
   ⇒ 那 3 个因子不是"随便挑的"，确实比在库里随机抽 3 个强得多。
2. **所以 strategy_004 输给基线，不是因为"选股层挑得差"，而是因为"骨架/权重结构"**：
   同一套 6 槽骨架下，把 3 个槽换掉 → 净值从 3.17 掉到 ~1.93~2.00（中位 −37%）；
   而方案 B 的 3 个槽已是这个骨架里的高位。**基线 3.60x 的领先来自它那套 4 因子结构本身**
   （每因子 1/4 权重、且含 `liq_amount` 这个最正交的分散来源），不是因为方案 B 挑错了因子。
3. **选股层有真实 alpha 得到再确认**（与 analysis_004 同向）：方案 B 与基线**双双**远超随机因子集分布。

**修正后的判断**：
- ❌ 旧表述「换/加因子都不通」→ **不准确**。准确的是：**"往基线骨架上加槽位 + 等权"这个结构动作有害**，
  而**因子本身挑得好**。
- ✅ 下一步应是**改结构而不是放弃因子**：例如**用 R076 直接替掉 `px_ma20` 或 `mom_20`（1 换 1，不增槽位）**，
  或用**非等权**（按 IC/正交性加权）合成 —— 而不是像方案 B 那样"加 3 个槽再等权稀释"。

## 诚实标注

1. **随机因子用了各自的最优方向**（analysis_005 样本内选的）⇒ 零假设被**抬高**（更严），
   方案 B 仍能落在 95 分位，结论**偏保守**而非乐观。
2. 20 次样本下 95 分位 ≈ 1/20，与 analysis_004 的诚实标注同理（符号检验 p≈0.05 边缘）；
   如需更紧的分位可扩到 50~100 种子（引擎进程内 ~10s/次）。
3. 本分析只回答「**3 个槽位随机 vs 方案 B 的 3 个**」；**没有**回答"6 个槽全随机"（用户已定只做前者）。
4. ρ 与抽样都在**同一份池、同一段样本**上，属**筛选口径**，非样本外验证。
