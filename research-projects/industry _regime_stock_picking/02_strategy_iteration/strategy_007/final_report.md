# 回测报告 — strategy_007（反向量能闸门）

> 结论先行：**通过 —— 本工程（004~007 系列）首个全项超越基线的迭代。**
> 引擎口径（trades）：**净值 4.566x / 年化 17.60% / Sharpe 1.145 / 回撤 −22.52% / 4,224 笔**
> vs 基线 **3.600x / 14.65% / 0.903 / −24.31% / 4,864 笔**（净值 **+26.8%**、Sharpe **+0.241**、
> 回撤浅 1.78pp、换手 −13%）。双对照全部过关。

> ⚠ **2026-10-15 修正记录（重要）**：本报告初版给出的 3.931x 建立在**有 bug 的拥挤度信号**上——
> 周聚合把「首个信号日之前的全部交易日」塞进第一周（一个多年巨量块），周序列只有 ~500 行
> ⇒ 滚动 104 周窗到 ~2017-12 才有真值，之前 NaN 被当 0 → **sc=0** ⇒ 2016-12~2017-12 的闸门
> **在无信息状态下**无条件关掉满仓动量周。修正为**全历史周网格**后（见 `shared/build_crowding_signals.py`
> 与云端同款修法），闸门关周 45 → **34**，绩效反升至 **4.566x**。详见 analysis_009 更新二。

## 1. 迭代设计

见 `main_idea.md`。唯一改动 = 空仓条件叠加一行：`动量周 AND top3 平均拥挤信号数 < 2 → 空仓`。
拥挤度信号来自 `shared/build_crowding_signals.py`（analysis_009 口径：
L1 成分聚合周频量能 6 因子 · 104 周滚动百分位 · ≥60 分位触发）。
选股/缓冲/权重/成本/引擎全同基线。

## 2. 口径与自检

- 引擎：**权重引擎** `local_weight_backtest.py`；行情 `engine_market_weekly_indpre_rawpx.parquet`（原始价）
- 成本 3/13 bps、min 5、lot 100、初始 50 万（config.json 与基线逐字段一致）；指标全部由 trades 推算
- **★ 自检通过**：本目录基线对照跑出 **3.6001x / 14.65% / 0.903 / −24.31% / 4,864 笔**，
  与 strategy_002 冻结基线**逐值一致** ⇒ 引擎无漂移
- 闸门实际关掉 **34 个满仓动量周**（按年：2016:1、2017:8、2018:7、2019:5、2022:9、2024:4）

## 5. 结论与归因

1. **量能闸门是真实的、且量级可观的增益**：+26.8% 净值 / +0.241 Sharpe，且不在场时间只多 2%
   （总空仓周 313 → 347 / 494）；
2. **机制**：动量周的行业层需要有量能背书（闸门关「无量能确认的假动量」），
   选股层四因子恒反转不动（analysis_011 三验），稳定性过滤不动（strategy_006 消融证 +1.23x）；
3. **与修正前对比**：初版 3.931x 之所以偏低，正是 2017 年那批**无信息关周**造成的——
   修正后把 2017 的关周从 15 减到 8，收益反而更高，说明那批周本来是赚钱的。

## 6. 改进建议 / 下一步

1. **阈值敏感性未做防过拟合处理**：sc<2、60 分位、104 周窗均为样本内主口径；
   下一步应做 sc∈{1.5,2,2.5} × 百分位∈{50,60,70} 网格 + 样本外折分；
2. **更窄的毒药格**：analysis_009-F 的「动量·刚开仓·无量能」格更毒 → 可试只在 streak 第 1 周启用闸门；
3. **行业层排序版**：闸门是二值版"行业选热"；可试动量 top-N 内按 sc 排序取前 3（连续版），
   与「排序≫开关」定律的对照实验；
4. **云端复跑**（本报告修正后重跑）：`cloud_code_iter7_crowdgate_v2.py`（已同步修正周网格 bug）。
