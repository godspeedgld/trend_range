# cs-trend-train — 手动趋势画线交易训练工具

在 K 线图上手工画趋势线、按「等额止损」提交交易（开仓时间/开仓价/止损/止盈），
后端自动按后续行情判定平仓（**只认你提交的止损/止盈价**），并有一套独立的
交易记录与统计页面（清单 + 胜率/盈亏比/净值曲线/夏普/肥尾率）。
像 TradingView 一样画线，但线和交易记录落在本地 JSON，可反复加载复盘。

## 启动

```bash
python cs-trend-train/server.py
# → http://127.0.0.1:8710                  主图 · 股票（默认标的 中国平安，默认训练窗口 2020 全年）
# → http://127.0.0.1:8710/?src=future      主图 · **期货**（默认标的 螺纹钢主连 RB_DOMINANT.SHF）
# → http://127.0.0.1:8710/trades.html      交易记录与统计
# → http://127.0.0.1:8710/trades.html?src=future   期货的交易记录与统计
```

零第三方 web 依赖（标准库 http.server）；数据读本地 DuckDB warehouse；
前端只引**本地化的** klinecharts / plotly（CDN 不可达也免疫）。

## 期货模式（与股票**平行共存、互不影响**）

主图顶部有 **股票 / 期货** 切换（点一下整页重载，用 URL 参数 `?src=future` 表达）。
缺省（不带参数）= 股票 ⇒ **股票那边的一切行为与加期货之前完全一致**。

| 项 | 股票 | 期货 |
|---|---|---|
| 数据表 | `stock_bar1d`（本仓库） | **`future_daily_post`**（pandadata 仓库；主力连续·**后复权**） |
| 标的 | 全市场 5,829 只 | 72 个商品品种主连（`RB_DOMINANT.SHF` 形式），拼音检索可用中文名 |
| 记录/设置 | `data/lines.json` 等 4 个 | **`data/lines_future.json` 等 4 个**（独立文件，互不干扰） |
| 默认风险额度 | 5,000 | **10,000**（"每次止损 ≤ 1 万"） |
| 仓位反算 | `股数 = 风险额度 ÷ (买−止损)`，向下取整到 100 股 | **`手数 = 额度 ÷ ((真实买−真实止损) × 乘数)`**，保底 1 手 |
| 额外记录 | — | `multiplier` / `margin_rate` / `margin_used` / **`real_buy_price` / `real_stop_price` / `real_tp_price` / `real_exit_price` / `entry_dominant` / `exit_dominant` / `roll_pts` / `pts_real`** |
| 盈亏 | `(卖−买) × 股数` | **`pts_real × 手数 × 乘数`**（真实点差，见下） |

### ★ 真实价映射 + 换月价差折算（2026-10-14）

**K 线本身仍是乘法后复权**（防止长历史出现负价）—— 图上价格 ≠ 真实盘面价（如螺纹当前
图上 ~4466 ≈ 真实 3093 × 1.47）。金额层全部按**真实价**折算：

- `真实价 = 复权价 ÷ 当日 adj_factor`；每根 bar 都带 `adjf` / `dominant`（当日主力合约号），
  tooltip 期货模式会显示「真实价 / 主力合约」。
- **手数 / 保证金 / 名义本金**：用**开仓日真实价**反算（此前用复权价，手数会少 ~1.47 倍、
  金额虚高 ~1.47 倍 —— 已修正）。
- **盈亏（换月价差已扣）**：真实点差 = 分段计算 `Σ段内(段末−段首) ÷ 段因子`，段 = 相邻换月之间。
  等价于用户公式：`(真实平−真实开) − Σ(远月换月价−近月换月价)`（远月贵 = 换月逆风，扣负值）。
  例：100 买 10 月合约 → 换月（11 月合约贵 5）→ 120 平 → 记 **15** 点而非 naive 的 20 点。
  记录里的 `roll_pts` = 被扣掉的换月价差合计（正 = 换月逆风）；`pts_real` = 扣完后的真实点差。
- 做空同理（分段后取负）；R / 收益率也按真实点差算。

**数据表怎么来的**（脚本在 `data_cache/pandadata_warehouse/`，可重跑）：

- `build_future_daily_post.py`：本地有两份期货数据，各有长短 ——
  `future_daily`（**未复权**，主力连续换月有 **±10% 假跳空**，会直接把画线的止损线打穿）
  × `pd_k_data.db [1d_k_data]`（**已后复权**，但字段少）。
  内连接成 `future_daily_post` = **既复权又字段全**；顺带把 `settlement/limit_up/limit_down`
  也乘上同一 `adj_factor`（否则表内坐标系不一致）。**不动**原表。
  校验：换月日 |涨跌| 中位 **0.00%**、最大 20 个涨跌幅里换月占 **0/20**。
- `build_future_meta.py`：品种表（`code/中文名/类别/乘数/保证金率`），
  主源 `temp/保证金.xlsx` 的「商品」sheet（`保证金1` 列反推费率），可覆盖 64/72 个品种。

⚠ **缺元数据的 8 个品种**（`AD/FB/LU/OP/PG/PR/RR/WR`）可以看 K 线，但**不能开仓**
（反算手数需要乘数）—— 往 `future_meta` 补一行即可。

## 统计口径

只统计**已平仓**的笔（止损止盈都没触及的「持仓中」单列，不进统计）：

```
R = (平仓价 − 开仓价) / (开仓价 − 止损价)      ← 价格层量，不需要股数（老记录也能算）
胜率 = 盈利笔数 / 已平仓笔数      盈亏比 = 平均盈利R / |平均亏损R|     期望R = 平均R
肥尾率 = 收益率 ≥ +30% 占比      （与 analysis_012/014 的 is_tail = ret >= 0.3 同口径）
夏普 = 平均R / R标准差 × √(252 / 平均持仓天数)，另给不年化的「逐笔夏普」
期末净值 = (初始资金 + Σ盈亏) / 初始资金     ← 初始资金在 ⚙设置（默认 100 万），仅作分母不影响仓位
年化收益 = 净值^(365/跨度自然日) − 1         ← 跨度 = 最早开仓日 → 最晚平仓日（复合年化）
净值曲线 = 累计 R（左轴）+ 累计盈亏（元，右轴虚线）
```

## 标的检索（代码 / 名称 / 拼音首字母）

`zxgj` → 中芯国际、`zgpa` → 中国平安、`yh` → 一堆银行。**零依赖实现**：
GB2312 的一级汉字是按拼音排序的，所以把汉字编码成 GBK、看码位落在哪个区间，
就能直接推出声母首字母（`_PY_BOUNDS`，覆盖 6763 个常用字；生僻字/字母原样保留）。

多音字单独处理：码位区间只能给最常见那个音（`行`→X），但股票名里 `银行` 要 H ——
所以对少数几个字（`_PY_AMBIG`：行/重/长/参/藏/厦…）**生成全部变体**，命中任一即匹配
（`zsyh` 与 `zsyx` 都能搜到招商银行；中国重工/重庆钢铁同理）。

标的名称取**众数**而非 `any_value`：除权日会混进 `XD中国平` 这类脏名，取错就搜不到。
名称与首字母在服务端**惰性缓存**（1578 只，一次全量查询），之后每次搜索都是内存匹配。

## 数据

- 行情（股票）：warehouse `stock_bar1d`（后复权；`raw` 字段 = 后复权 ÷ adjust_factor）
- 行情（期货）：pandadata 仓库 `future_daily_post`（**主力连续 · 后复权**；同样有 `raw` 字段）
- ATR14：Wilder ewm(α=1/14)（与 hs300 工程 `shared/atr14_precompute.py` 同式）——当前**出场判定不用它**，仅随 K 线下发备用
- 记录：`data/lines.json` / `data/trades.json` / `data/settings.json`（按标的分组，肉眼可查可手改）
  + `data/notes.json`（交易心得，**扁平列表**不按标的分组 —— 统计页要跨标的看）
- 交易备注：存在交易记录自己的 `note` 字段里。⚠ **改交易记录时必须把 note 带过去**：
  `build_trade()` 只产出事实字段、不产出 note，upsert 时若不从旧记录搬一次，
  用户写的备注会被「修改交易」静默清掉（后端已处理）
- 交易字段：`entry_date / entry_source / buy_price / stop_price / tp_price / risk_amount / shares`
  （**写时的事实**）+ `exit_date / exit_price / exit_reason / holding_days`（判定结果），
  其余（R / 收益率 / 盈亏 / 状态）都是**读时算**的，改口径不必迁移历史

## 已知限制

1. **后复权价会被新除权事件回溯改写**：仓库刷新后整段历史 hfq 价平移，而判定用的是
   「当下的 klines」，与当初存进 JSON 的 `buy_price/stop_price` 可能不再同一坐标系 →
   止损线会错位。记录里存了 `adj:"hfq"` 备查
2. 同日既触止损又触止盈 → 按止损计（日内路径不可知）
3. 不计交易成本（毛收益）
4. 老记录（上一版 schema，无 `entry_date`/`shares`）：开仓日退回信号日、R 照常算，
   但股数/盈亏显示「—」（不反填止损额度，避免凭空造出从未发生过的仓位）
5. **期货主连的复权序列同样会被后续换月改写**（同第 1 条，只是触发事件从"除权"变成"换月"）
   ⇒ 翻旧记录时 `buy_price/stop_price` 可能已经"漂"了；但**真实价字段（real_*）是写时定格的**，
   不受后续改写影响。换月**当日**的收益在复权序列里记 0（该日的行情归入新合约段）
6. 期货「保底 1 手」会**经常触发**：一手名义可能远超 1 万（原油 SC 一手约 46 万、铜约 51 万），
   此时该笔的真实风险会大于设定的 1 万 —— 预览面板会显示实际占用，务必看一眼再提交
