# Regime 方法提取与验证规范（regime_extraction.md）

本文件是 **Step 4 Regime Verification（回测验证）** 的依据。
Step 4 含两个子步骤：4a 提取方法与参数（本文件）→ 4b 运行与输出（generate_regime_view.py）。

## 核心原则：状态划分严格按研报/论文

**不预设固定的状态集合。** 不同研报可能有不同的市场状态划分：
- 有的只分两类：趋势 / 震荡
- 有的分三类：趋势上升 / 趋势下降 / 震荡
- 有的分四类以上：牛市 / 熊市 / 高波震荡 / 低波震荡…

提取时**严格按原文的状态定义**。原文分几类就实现几类，不得增删或改并。

## 提取原则（严格按原文）

### 情况 A：原文有确切的市场状态划分方法

1. **严格按原文提取，不得擅自修改实现**。原文写什么公式就实现什么公式，原文给什么参数就用什么参数。
2. **多条件必须全部实现，不得选择性跳过**。无论 AND 还是 OR 关系，所有子条件都必须实现。
3. **计算难度大时**：先给出优化方案并说明理由，待用户确认后再执行，不得先斩后奏。
4. **仅数据不支持才允许近似**，且必须在报告中明确指出。

### 情况 B：原文没有确切的划分方法

1. 部分确切的部分严格按情况 A 执行。
2. 不确切的部分先从 `main_approach.md` 推导，再从原文 `_report_full.txt` 推导。
3. 仍无法确定时标注"原文未明确"。

### 多方法提取规则

- 如果原文有**多种** regime 划分方法，**每种都必须提取**，不得只取一种。
- 每种方法独立实现，独立输出，独立记录参数。

## 4a 产出三件

### 1. regime_methods.md（文字描述）

对每种方法记录：
- **方法名称** + 来源章节
- **状态定义**：原文划分了哪几类状态（严格按原文，如"趋势/震荡"两类或"上升/下降/震荡"三类）
- **划分逻辑**：什么条件下判为什么状态（含阈值）
- **公式**：精确公式 + 变量定义
- **参数**：所有参数值（窗口、阈值、乘数等）
- **代码引用**：`regime_impl.py` 中对应函数

### 2. regime_impl.py（可执行代码）

"教材式"可审计实现。必须暴露：
```python
def classify_regime(df) -> dict:
    """返回每种方法的市场状态分类。

    Returns:
        methods: dict[str, pd.Series] — 方法名 → 状态序列
                 状态值：任意可哈希值（int/str），由原文状态定义决定
                 如两类: 0/1；三类: -1/0/1；或字符串 'bull'/'bear'
        state_labels: dict — 状态值 → 中文标签
                 如 {-1: '趋势下降', 0: '震荡', 1: '趋势上升'}
        params: dict — 所有参数值
    """
    return {'methods': {...}, 'state_labels': {...}, 'params': {...}}
```

参数集中放在 `PARAMS` 字典。

### 3. data_params.json（数据参数记录）

额外记录数据相关参数：
```json
{

  "symbol": "000300.SH",

  "adjustment": "无（指数）",

```

## 4b 运行与输出（generate_regime_view.py）

```bash
python scripts/generate_regime_view.py {project_dir} --market-data <OHLC CSV/Parquet>
```

**输出三件套**：

1. **regime_segments.md** — 表格化各时间段划分：每种方法每段的起始日/结束日/状态/天数
2. **regime_stats.json** — 统计：各状态天数/占比
3. **regime_view.html** — 可视化：close 曲线 + 状态背景着色

颜色方案（按语义自动映射）：
- 上涨/牛市类 → 浅红
- 下跌/熊市类 → 浅绿
- 震荡/中性类 → 浅蓝
- 其他状态 → 预留色板（浅黄/浅紫/浅橙/浅灰）

## 4c 可视化出错的如实报告（必读）

严格按研报/论文复现时，若 regime 输出结果**过于碎片化**导致可视化输出错误或无意义（如 HMM 单变量观测状态频繁跳变，时间段划分表上千行、每段仅 1-2 天），**必须在 `final_report.md` 如实说明，不得回避或掩盖**。

报告需包含：
1. **现象**：碎片化的量化表现（状态切换次数、区段数量、占比等）
2. **根因**：数据限制（多资产→单资产）、观测变量选择（return 类 vs MA 类）、还是方法本身的固有特性
3. **已尝试的解决路径**及结果（换观测变量、调参数、平滑后处理等）
4. **结论**：该碎片化是"方法局限"还是"复现条件不足"

> 原则：反复尝试后，若数据限制或研报/论文方法本身导致可视化出错，如实写进 final_report，这是诚实复现的一部分，而非失败。
