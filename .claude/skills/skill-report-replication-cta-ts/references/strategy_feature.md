# 回测特征提取规范（strategy_feature.md）

本文件是 **Step 4 回测特征提取**的依据，产出 `03_backtest_strategy/backtest_features.md` + `reference_implementation.py`。

## 提取原则（优先级从高到低）

### 情况 A：原文有确切入场/离场/交易规则描述

1. **严格按原文提取，不得擅自修改实现**。原文写什么步骤就实现什么步骤，原文给什么参数就用什么参数。
2. **多条件必须全部实现，不得选择性跳过**。如果原文某个判断由多个子条件构成（无论 AND 还是 OR 关系），**所有子条件都必须严格实现**，不能因为某个子条件计算难度大、实现复杂等理由就擅自跳过。
   - 例：regime 判断条件"TSI 置信区间完全位于零轴一侧，**或者** |TSI| 历史分位 > 50%"。两个子条件是 OR 关系——**不能**因为前者需要 bootstrap 重采样数千次计算量大就只实现后者。
   - 例：入场条件"A **AND** B **AND** C"——不能因为 B 难以实现就跳过 B 只做 A AND C。
3. **计算难度大的处理流程**：如果某个子条件确实因计算资源/环境限制难以直接实现，必须：
   - ① 先给出优化方案或近似方案并说明理由
   - ② 待用户确认后再执行
   - ③ **不得先斩后奏**——不能擅自跳过再在偏差表中标注
4. **引擎不支持时，必须修改引擎**。如果原文的入场/离场/交易规则，当前回测引擎不支持，**不得擅自回避或降级**，必须修改回测引擎使其支持，严格按原文结果实现。
5. **入场/离场/交易规则不得擅自改动**。原文写 t+1 开盘入场，就必须 t+1 开盘入场；原文写分钟线止损，就必须按分钟线口径。**只有本地数据不支持才能近似，但必须在报告中明确指出近似之处**。
6. 如对原文描述有理解不清之处：
   - ① 先查 `02_approach/main_approach.md`（Step 3 产出，已结构化展开公式和推导）
   - ② `main_approach.md` 仍无法解决时，回到原文 `_report_full.txt` 对应章节确认
   - ③ 不再从本地 PDF 重新读取——`_report_full.txt` 是权威文本源

### 情况 B：原文没有确切入场/离场/交易规则描述

1. **部分确切、部分不确切**：确切的部分**完全按情况 A 所有要求执行**（含多条件全部实现、不得跳过等）；不确切的部分按下条处理。
2. **不确切的部分**：
   - ① 先从 `02_approach/main_approach.md` 总结提取最贴近原文描述的版本
   - ② `main_approach.md` 无法解决时，从原文 `_report_full.txt` 中推导
3. **仍无法确定时**：标注为"原文未明确"，不自行编造默认值。

### 提取后实现准则

- **代码严格按提取结果实现，不得擅自修改**。提取结果中的步骤、参数、口径即为代码实现的唯一依据。
- **逐条标注来源和偏差**：每条特征追溯到原文章节（实证 §X 或 main_approach §Y）。每个与原文的差异在 backtest_features.md §4 逐条列出并说明原因（仅限引擎/数据不可抗力，不得以"v1 简化"为由擅自偏离）。

## 三特征模型

只提取三个特征，每项**文字描述 + 可执行代码**：

### 1. 入场逻辑

研报实证中**什么条件下开仓**，把 regime 门控、信号触发、方向判断统一描述为一个完整入场规则。

- 范例："收盘上穿自适应均线 AND regime=趋势上行 → 做多；下穿 AND 趋势下行 → 做空"
- 若研报用 regime 门控，则入场逻辑统一描述"regime 条件 + 信号条件"的 AND 组合
- 代码：`entry_signal(df) -> (entry_long, entry_short)` 布尔事件数组

### 2. 离场逻辑

研报实证中**什么条件下平仓**，覆盖止损、止盈、时间退出、信号反转等所有离场路径。

- 范例："ATR(14) 吊灯移动止损 k=2.0，持仓中 high/low 命中即平仓；无主动止盈；不反手"
- 若有多层退出（技术止损 + 逻辑证伪 + 时间退出），逐一列出，并标注实证中实际启用了哪几层
- 代码：止损规格 `{"type":"atr_chandelier","atr_period":14,"k":2.0}`，引擎据此状态机触发

### 3. 交易规则

研报实证中的**仓位、风控、成本、品种、频率等约束**。

- 范例："满仓（信号 ±1 即满仓多/空）" / "vol-target 15%，vol_window=20"
- 包含：仓位法、手续费、滑点、保证金、年化天数、是否允许做空、单品种最大权重
- 代码：`sizing` spec + 引擎 CLI 参数

## 数据与参数

额外记录：
- 品种、区间、频率、数据来源
- 所有策略参数（窗口、阈值、乘数）

## reference_implementation.py

`03_backtest_strategy/reference_implementation.py` 必须以"教材式"可审计风格实现入场/离场/交易规则的相关函数：
- `entry_signal(df) -> (entry_long, entry_short)` — 入场
- `stop_spec() -> dict` — 离场（止损规格）
- 参数集中放在 `PARAMS` 字典

`strategy.py` 直接 import 这些函数，暴露 `build_strategy(df)->spec` 喂引擎。

## check_strategy.py 检查

门禁检查 backtest_features.md 含：**入场逻辑/离场逻辑/交易规则** 三节关键词，且每节有文字+代码引用。reference_implementation.py 有函数定义。
